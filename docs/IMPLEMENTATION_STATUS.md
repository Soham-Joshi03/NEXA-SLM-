# Implementation Status

## Files currently in the repository

### `train.py`
The uploaded `train.txt` was renamed to `train.py` and committed without intentional changes to the model/training logic. It contains:
- `Config`: model, training, dataset, and checkpoint settings.
- `MemmapDataset` and `cycle`: memory-mapped uint16 token dataset and infinite loader iterator.
- `SwiGLU`, `MoELayer`, and `Mamba3Layer`.
- Rotary embedding helper and `SWGQA`.
- `SuperBlock` and `PerfectSLM`.
- Single-file checkpoint saving and the Accelerate training loop.

The uploaded file passed Python bytecode compilation locally before being pushed.

### `inference.py`
The supplied inference script provides:
- Single-token Mamba state updates with convolution and SSM caches.
- Single-token SW-GQA processing with a pruned sliding KV cache.
- Hybrid layer traversal for Mamba/MoE and SW-GQA/shared-MLP paths.
- Temperature and top-k sampling.
- Autoregressive generation with scratchpad and prompt prefill.

It imports `Config`, `PerfectSLM`, `Mamba3Layer`, `SWGQA`, and `apply_rotary_emb` from the root-level `train.py`.

### Tokenizer configuration
The supplied ByteLevel BPE tokenizer JSON is stored as two consecutive text fragments under `tokenizer/` to preserve the full uploaded file. The fragments were concatenated and validated as JSON after upload:
- 32,768 vocabulary entries.
- 32,501 BPE merge rules.
- 11 added special tokens.

Reconstruct the exact root-level tokenizer file using:

```bash
python scripts/assemble_tokenizer.py
```

The script writes `jamba_bbpe_tokenizer.json` and validates that the reconstructed file is valid JSON.

## Training prerequisites and important configuration

The current training script expects the following dependencies:
- PyTorch
- NumPy
- Hugging Face Transformers
- Hugging Face Accelerate
- `mamba-ssm` with the selective-scan extension available for the installed CUDA/PyTorch environment

The dataset paths in `Config` point to Kaggle input files:

```text
/kaggle/input/datasets/ommahadeokar/dataandtok/train.bin
/kaggle/input/datasets/ommahadeokar/dataandtok/val.bin
```

The script expects each binary dataset to contain uint16 token IDs. Update `Config.train_bin` and `Config.val_bin` for a different environment, and ensure the token IDs fit the tokenizer vocabulary.

The default training configuration is large (batch size 4 per GPU, 64 gradient-accumulation steps, 2,048-token sequences, and 10,000 global steps). Do not launch it unchanged on a constrained GPU without first reducing settings and validating memory use.
